# Alpha Scene Director design

## Goal
An installable ComfyUI custom-node package for a film prepared as 8â€“12 scenes. Each scene can contain multiple short clips and written prompt points. It accepts uploaded first/last snapshots, submits one existing first/last-frame video workflow per clip, carries actual final frames forward, and saves resumable progress.

## Architecture
Two V1 nodes (the API is still officially supported), a full-screen browser scene editor, and an asynchronous server runner. AlphaSceneDirector supplies images, text, seed, frame count, frame rate, derived duration and naming to an existing video workflow. AlphaSceneCheckpoint passes decoded IMAGE frames through, saves the first and last PNG and an atomic receipt. The existing video saver remains responsible for encoding. The server runner uses ComfyUI's public /prompt, /queue and /history endpoints outside node execution. The destination is derived from the actual inbound server socket, never a supplied Host or arbitrary URL. Browser closure does not cancel a run. ComfyUI restart requires an explicit Resume.

## Contracts

Plan JSON: version=1, project (string), global_prompt, negative_prompt, defaults {first_image,last_image,frames=81,fps=16,seed=1}, scenes (1â€“12; typical 8â€“12). Each scene has id, title, prompt, optional direction {shot,camera,light,look}, first_image,last_image,frames,fps,seed,negative_prompt,input_overrides and clips. clips is an integer (repeat scene prompt) or an array of objects with optional prompt,direction,first_image,last_image,frames,fps,seed,negative_prompt,input_overrides. Direction values are allowlisted prompt terms. Maximum 1000 expanded clips. Image names are paths relative to ComfyUI input. @previous denotes the preceding actual last frame. Default first image is the global first image for clip one and @previous thereafter. Every last target must resolve explicitly or from scene/global defaults. Reusing a last target is supported; users should supply intermediate targets when the story needs them.

Compiled clip dict: id (sNN-cNNN generated unique), scene_id, scene_title, prompt (global + scene + clip), negative_prompt, first_image, last_image, frames, fps, seed, input_overrides. Paths and numeric bounds are validated. Input overrides map existing node IDs to scalar widget inputs and cannot rewrite links or control nodes.

director_core.py: PlanError(ValueError); compile_plan(plan, fallback=None)->list[dict]; validate_workflow(workflow,director_id,checkpoint_id,video_output_id)->`frames|duration`; build_prompt(workflow,clip,job_id,attempt_id,director_id,checkpoint_id,video_output_id,previous_frame=None)->dict; safe_path(root,relative)->Path; atomic_json(path,data)->None; read_json(path)->dict.

AlphaSceneDirector required widgets: scene_plan (STRING multiline), first_image (STRING), last_image (STRING), positive (STRING multiline), negative (STRING multiline), seed (INT), frames (INT), fps (FLOAT), run_id (STRING default preview), clip_id (STRING default clip-001). Output indices: 0 IMAGE first_image; 1 IMAGE last_image; 2 STRING positive; 3 STRING negative; 4 INT seed; 5 INT frames; 6 FLOAT fps; 7 STRING filename_prefix; 8 STRING run_id; 9 STRING clip_id; 10 FLOAT duration_seconds (`frames / fps`). Each queued prompt replaces these scalar widgets with the compiled clip, job UUID and unique attempt ID. Filename prefix alpha_scene_director/<job_id>/<attempt_id>. No latent denoising state is saved.

AlphaSceneCheckpoint required inputs: images (IMAGE), run_id (STRING forceInput), clip_id (STRING forceInput). Returns the same IMAGE batch, OUTPUT_NODE=True. Copies decoded frame 0/-1 into input/alpha_scene_director/<job>/<attempt>_first.png and ..._last.png; receipt in output/alpha_scene_director/<job>/<attempt>.receipt.json: {job_id,attempt_id,first_frame,last_frame,frame_count,width,height}. Receipt alone is not proof of successful video completion.

runner.py: JobManager(root,input_root,client_factory). root is output/alpha_scene_director. client_factory is callable returning a public-Comfy-API adapter with async submit(prompt,prompt_id), history(prompt_id), queue_ids(). Manager create(request)->dict, get(job_id)->dict, list_jobs()->list[dict], pause(job_id)->dict, resume(job_id)->dict, validate(request)->dict. create/request fields: plan,workflow,director_id,checkpoint_id,video_output_id. create persists before launching asyncio task. validate resolves all static endpoints and graph structure before creating work. Job state saved atomically at root/<job_id>/job.json, immutable frozen workflow/plan, sequential clip records. Each record retains attempt_id, prompt_id before POST, status, receipt and saved video files. HTTP acceptance ambiguity reconciles queue/history, otherwise stops as interrupted without automatic retry. Resume first reconciles the outstanding prompt and never duplicates a known queued/running one. Missing history after a full server restart rerenders only the unconfirmed clip. Success requires history status.completed=true,status_str=success, receipt and selected output's video artifact files all present. Completed clip receipt/video files are rechecked before resume. No automatic unbounded retries. Pause finishes current clip, then stops; Resume never reruns completed clips. Only one active job per manager, rejects duplicate Start while running. job public shape: job_id,status,completed,total,current,error,estimated_seconds,clips. Browser receives this shape, may receive additional local metadata.

Public-API adapter lives in server_api.py; manager never receives auth headers in a persisted request. Server routes: GET /alpha_scene_director/jobs; POST /alpha_scene_director/validate; POST /alpha_scene_director/jobs; GET /alpha_scene_director/jobs/{job_id}; POST .../{job_id}/pause; POST .../{job_id}/resume. Adapter uses aiohttp with trust_env=False, no redirects. Its endpoint and auth headers exist only in memory. Fresh Resume replaces the adapter context from the current request. Errors return {error:string} with a non-2xx status.

Browser extension: app.registerExtension + nodeCreated hook. Director gets an Open Scene Director button. A full-screen native HTML Cinematic Studio workspace edits all scenes before run (default ten), global prompt, negative prompt, defaults/first/last uploads, editable clip count plus advanced per-clip JSON, per-scene Shot/Camera/Light/Look prompt controls, start/end image and prompt, and optional scalar input_overrides. Import/export plan JSON. Explicit checkpoint and video-output selectors. Runs app.graphToPrompt and posts output API graph; no UI workflow JSON confusion. Polls progress, can pause/resume and reconnect by existing job ID after a refresh. Saves scene_plan widget and last job ID in node properties. Uses textContent for user strings. Uses api.fetchApi and standard /upload/image with input type and a unique subfolder. Never embeds credentials in plan JSON.

## Verification and scope
Meaningful tests use stdlib unittest, real filesystem persistence and a controlled public-API boundary. Test deterministic expansion, path traversal refusal, overrides/link protection, initial scene validation, serial queueing, failed generation, missing outputs, uncertain submissions, browser-independent run state, pause/resume/restart and duplicate-job protection. Test frontend data serialization with node:test. No installed ComfyUI or GPU exists in the authoring workspace, so live generation/UI verification must be reported as pending. Package source, tests, install README and an original-adult dance scene plan. A custom controller cannot confer endpoint conditioning or arbitrary duration on an incompatible video model.
